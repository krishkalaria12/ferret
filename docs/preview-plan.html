Detailed implementation plan · F-30–F-36 · F-75 · 6 Sep 2026

Beautiful previews for every file type.

A resizable pane on the right that renders whatever is selected — Markdown as a document, source as highlighted code across sixty-plus languages, images, PDFs, CSV as a grid — and keeps rendering it as you arrow down a directory, with bounded reads, bounded memory, and responsive navigation.

The product requirementSelect a file and see its content in a persistent right-hand pane: beautifully rendered Markdown, syntax-highlighted code in at least 60 distinct languages, PDF pages and images. The supplied reference establishes the side-by-side layout, a quiet header and an uninterrupted reading surface beside the browser and terminal. Ordinary supported files must render; metadata fallback is for unsupported, damaged, protected or over-budget inputs, not a substitute for promised PDF support. This document is a plan only.

Decision summary

Executive verdict

Almost every renderer this feature needs is already compiled into the tree and switched off. gpui-component ships a Markdown document view, a Rope-backed virtualised code editor, a tree-sitter highlighter with a publicly extensible language registry, and a table; gpui decodes fifteen image formats and SVG; ferret-vfs’s read already takes a byte budget. The work is not writing renderers. The work is a classifier, a byte budget, one background pipeline, and the two or three places where the stock behaviour is actively wrong for a file manager.

Recommended baselineTurn on gpui-component’s tree-sitter-languages feature for 35 grammars; register roughly 30 more through the public LanguageRegistry for 65+; render Markdown with TextView, code with a read-only Editor, images with our own capped decode into a RenderImage, tabular data with table, PDF through a bundled, isolated Pdfium backend, and additional document/media formats through the operating system’s thumbnail service behind one ferret-platform trait.
PV-D01

One registry, one Preview value. Classification and reading happen once, on a background thread, and produce a plain data value. The Render impl only reads it. This is gate 7 (“no per-frame work may be O(the directory)”) applied to a pane whose input is O(the file).

PV-D02

ferret-preview is GPUI-free; the pane lives in ferret-ui. Only ferret-ui may depend on gpui-component, and every renderer worth reusing is inside it. So the crate seam falls between what to show — sniffing, budgets, decoding, parsing, caching, all testable without opening a window — and how to draw it.

PV-D03

No unbounded file reads. Rust providers use Vfs::read(path, budget). Small files may be read completely; native path-based thumbnail APIs are a separate, explicitly gated exception (see PDF). Budgets are per kind and live in ferret-preview/src/config.rs. A file past its budget previews its head with an explicit “first 2 MB of 4.1 GB” banner — never a spinner that never ends, never a blank pane.

PV-D04

Code preview and edit mode are the same component. gpui-component’s Editor with readonly(true) gives virtualised line layout, selection, in-pane find, line numbers, folding and tree-sitter highlighting. F-36 reuses that renderer, adding a complete lossless buffer, save capability and navigation guards. Upstream states the editor is built for “large text up to about 50K lines”, so the line cap in PV-D03 is not a preference — it is that ceiling, enforced before we hand text over.

PV-D05

Extend the highlighter; do not replace it. LanguageRegistry::register(name, &LanguageConfig) is public and takes a tree_sitter::Language plus query strings, so additional grammar crates drop straight in and are picked up by the editor and by Markdown’s fenced code blocks with no second theme mapping. This answers Q-02.

PV-D06

Identifying a language and highlighting it are different jobs. A table of ~240 extensions resolves a language name; 65+ of those names have a grammar behind them. An .applescript file previews as monospaced text labelled AppleScript, not as “unsupported binary”. Coverage of the header is total; coverage of colour is finite and honest.

PV-D07

The OS extends format coverage. Quick Look on macOS and IShellItemImageFactory on Windows provide best-effort thumbnails for installed document and media handlers. HEIC, RAW, Office and video support is capability-dependent, not universal. One ThumbnailProvider trait in ferret-platform, shaped exactly like the existing IconProvider and bound by the same rule: never called on the render path.

PV-D08

Reliable PDF rendering is part of the release. Ship a pinned Pdfium binary with official macOS and Windows builds, behind the Rust pdfium-render wrapper in a supervised helper. A native thumbnail may give an early cached image, but installed shell handlers never decide whether ordinary PDFs work. Page one and page navigation ship in Phase 3; continuous multi-page scrolling is later. Developer builds may disable pdf, but that reduced build does not satisfy F-34.

PV-D09

Decode images ourselves; never hand img() a user’s path. GPUI’s asset loader does a blocking whole-file fs::read and a full-resolution decode. That is correct for the app’s own bundled assets and wrong for a 200-megapixel TIFF someone arrow-keyed past. Probe the header for dimensions, refuse past a pixel cap, decode with limits off-thread, downscale to the pane, and hand GPUI a finished RenderImage.

PV-D10

The preview never touches the network. GPUI resolves a non-file image URI by fetching it over HTTP. A README in a downloaded folder must not be able to make this machine call out — that is a tracking pixel with a file manager attached. Markdown resources pass through a bounded, document-scoped resolver and arrive as decoded bitmaps; raw URI and path image loading is forbidden. Remote selected files may use their explicit VFS connection; document resources never initiate additional network access.

PV-D11

One generation, debounced, cancel-by-drop. The same contract the listing and Power Search already use. An uninterrupted key-repeat sweep settles on one request; every result carries its generation and a stale one is discarded defensively.

PV-D12

A remote preview is the same code with a smaller budget. Vfs::read already spans backends, so SFTP needs no provider of its own — it needs quarter budgets, an explicit “loading over the network” state, and capabilities_for(path) deciding whether the Edit button exists at all.

PV-D13

Edit saves atomically or refuses. Temp file in the same directory, flush, rename; line endings, final newline and permissions preserved; an identity/content change since load blocks the save, subject to the filesystem race limitations detailed in Edit mode. This needs a genuinely new Vfs method — the trait has no write today — and it is the one place in this plan where R-06 (data loss) is in play.

Traceability

Source, scope, and non-goals

The reference screenshot is a product reference, not an instruction. docs/plan.html stays authoritative: F-30 the pane, F-31 Markdown, F-32 highlighted code, F-33 images and thumbnails, F-34 PDF, F-35 CSV grid, F-36 in-place editing, plus F-75 space-to-preview. The base shell’s gates — virtualisation, focus, both themes, both platforms, run it, no O(n) per frame — apply unchanged.

Explicit non-goals

  • Not an editor. No LSP, no multi-file, no project, no diagnostics, no format-on-save. F-36 is “fix a typo in a config file without leaving the file manager”, and the moment it grows a second file it has become the wrong product.
  • Not a viewer for everything. Where neither Rust nor the OS can render a type, the pane shows metadata and an Open with… affordance. That is a finished state, not a failure state.
  • No transcoding. Video and audio get a poster frame and metadata; playback is out of scope for phase 3 and probably forever.
  • No archive browsing. A .zip previews as its manifest at most. Mounting archives as folders is a different feature and belongs with the VFS backends.
  • No thumbnails in list view. F-33’s thumbnails are for icon view. A 200,000-row list must not sprout 200,000 decode jobs.
Product experience

Pane anatomy

Two rows: a header that is identical for every file type, and a body that is entirely the provider’s. Keeping the header type-independent is what makes arrow-keying feel like one surface rather than seven.

Divider · 1 px + 6 px grab slopDrag-resizable, ResizeLeftRight cursor, hover tint at primary/35%. Double-click restores the default width. Same code shape as render_sidebar_divider.
Header · leftFile name (truncated middle, never wrapped), then a muted second line: kind · size · modified. The kind is the resolved language or format name — “Python”, “PNG image”, “PDF document” — not the extension.
Header · rightEdit (F-36, conditional) · overflow menu: Open with…, Reveal, Copy path, Word wrap, Line numbers, Show hidden characters.
BodyOne provider, filling the remaining height, scrolling in its own container. Nothing here is shared between providers except the scroll position reset on selection change.
Footer · only when it has something to sayA single muted line for truncation, capping, decode fallback or staleness: “Showing the first 2 MB of 4.1 GB.” · “Scaled from 9504 × 6336.” · “Page 1 of 812.” Absent otherwise — an always-present status strip becomes furniture nobody reads.

Visual quality is part of acceptance

Use a quiet shared surface and thin divider, with content given most of the pane. Default width is 42% of the available browser workspace, clamped to 320–720 logical px and persisted after resize. Preserve the terminal beneath the file list, with the preview spanning the remaining content height as in the reference. At small window sizes collapse the preview before the sidebar; never squeeze the file pane below its base minimum.

Markdown uses 16 px body text, 1.6 line height, a maximum 72-character reading measure and 24 px padding (16 px in narrow panes). Give headings a clear hierarchy, code fences a subtle themed background and horizontal scrolling, tables aligned cells, and images preserved aspect ratio. Code uses the configured monospace font at a 14 px baseline with 1.5 line height and line numbers off by default. Images use fit-to-pane with an alpha checkerboard where needed; PDF pages keep their document-white background against the themed surround. All values are initial design defaults to validate at 1180 × 760, 760 × 480 and 1×/2× scaling, in both themes.

Test the actual reading experience: selecting README → Python → PDF → image retains the pane width, never moves list focus, resets body scroll and never pairs a new filename with old content. Copy/select must work in text; icons and controls have accessible names, keyboard focus rings and disabled states. Opening the larger overlay reuses the current bitmap immediately, then requests a bounded higher-resolution replacement if needed.

Architecture

Four crates, one seam

The layering rule decides this before taste does: no service crate may depend on ferret-ui, and only ferret-ui may depend on gpui-component. Every renderer worth having is inside gpui-component. So the seam is data in, elements out.

1 · ferret-vfsBytes, budgeted

read(path, budget) exists and is already capped. F-36 adds a capability-gated atomic save contract; the existing read returns a bounded buffer, not a streaming or range handle.

2 · ferret-previewWhat to show

GPUI-free. Sniffing, classification, decoding, CSV parsing, thumbnail cache. Returns a Preview.

3 · ferret-platformWhat the OS can show

ThumbnailProvider: Quick Look and the shell thumbnail service, returning the existing IconBitmap.

4 · ferret-uiHow to draw it

preview/: the pane, the divider, the header, and one render arm per Preview variant. Owns the language registry wiring.

The value the pipeline produces

// crates/ferret-preview/src/preview.rs
pub enum Preview {
    /// F-31. Source plus the directory it lives in, which is what makes
    /// relative image links resolvable — and, per PV-D10, resolvable only
    /// downward from there.
    Markdown { source: String, base: VfsPath, truncated: Truncation },

    /// F-32. `language` is a registry name ("rust", "nix"), never an
    /// extension. `Plain` is a language, not an absence of one.
    Code { text: String, language: SmolStr, truncated: Truncation },

    /// F-33. Already decoded, already downscaled, in the BGRA layout
    /// `RenderImage` wants (validate stride and alpha convention). `natural` is the size before scaling, so the
    /// footer can be honest about it.
    Image { bitmap: Bitmap, natural: (u32, u32), frames: BoundedFrames },

    /// F-34 and everything the OS knows how to draw. `by` records which
    /// path produced it, because "Quick Look" and "pdfium" fail differently.
    Rendered { bitmap: Bitmap, pages: Option<Pages>, by: RenderedBy },

    /// F-35. Header row detected, delimiter sniffed, rows virtualised.
    Table { header: Option<Row>, rows: Vec<Row>, delimiter: u8, truncated: Truncation },

    /// The floor. Hex plus printable ASCII for the head of the file.
    Binary { head: Vec<u8>, size: u64 },

    Directory { entries: Option<u64> },
    Multiple { count: usize, bytes: u64, kinds: SmallVec<[(Kind, usize); 4]> },
    Unsupported { kind: Kind, reason: Unsupported },
}

Two properties of this enum are load-bearing. It is Send and owns everything it points at, so it crosses from a background task to the view without borrowing anything that might have been dropped. And it carries no GPUI type — Bitmap is width, height and a BGRA Vec<u8>, the same shape ferret_platform::IconBitmap already validates at the unsafe boundary — which is what keeps the crate’s tests running without a window. This is a shape sketch, not a complete API: carry source identity and generation in a result envelope, distinguish unknown sizes from zero, and use shared immutable buffers so pane and overlay do not clone payloads. PDF values hold a helper-session token and current page metadata; page requests remain outside Render. Encodings and losslessness are preserved alongside text.

Host supervised native work in a helper mode of the existing executable initially: ferret owns process launch/lifecycle, ferret-preview owns bounded requests and Pdfium work, and ferret-platform owns OS thumbnail calls. Use a versioned private IPC protocol with checked lengths, dimensions, request IDs and no arbitrary commands. A process boundary contains crashes but is not a security sandbox; constrain capabilities and resource use explicitly. Add another crate only if helper code gains an independent responsibility.

Why the grammars live in ferret-ui and the names live in ferret-previewLanguageRegistry is a gpui-component type, so the tree-sitter-* crates have to be ferret-ui dependencies. The extension-to-name table has no such constraint and belongs with classification. A grammar added without a name, or a name added without a decision about its grammar, fails that test.
Classification

Deciding what a file is

Extension first because it is free and usually right; content second because it is the only thing that is reliably right. A .txt that is actually a 900 MB core dump must not reach the text renderer, and a Makefile with no extension at all must.

  1. Name table. Exact filenames before extensions: Makefile, Dockerfile, Cargo.lock, .gitignore, CMakeLists.txt, go.sum, Justfile, .env. This is the case a pure extension map gets wrong every time, and it covers a lot of what sits in a repository root.
  2. Extension table. ~240 entries mapping to a Kind and, for text kinds, a language name. Built once as a static phf-shaped match — a plain match on a lowercased SmolStr, which the icon layer already established as the right representation for an extension.
  3. Magic bytes. The first SNIFF_BYTES (8 KiB) decide format for anything the name did not settle, and override the name for images and archives: PNG, JPEG, GIF, WebP, TIFF, BMP, ICO, AVIF, QOI, PDF (%PDF-), Zip, Gzip, ELF, Mach-O, PE, and the UTF-8/16/32 BOMs.
  4. Binary test. Check BOMs before testing NUL bytes: UTF-16/32 naturally contain NULs. Strictly decode BOM-marked text; otherwise validate UTF-8, allowing an incomplete trailing code point only at the read boundary. Unknown invalid text falls back to hex. Lossy display must be labelled and never editable.
  5. Size gate. Applied last, per kind, before any full read is attempted.
The sniff is a second read, and that is fineReading 8 KiB and then reading 2 MiB looks wasteful until you price the alternative: reading 2 MiB of a 4 GB video to discover it is a video. The sniff is one read(path, SNIFF_BYTES); the current API has no offset or continuation handle, so the provider rereads the prefix within its final budget. Count both calls and their bytes in benchmarks; do not concatenate the sniff with a second read from offset zero.

Symlinks are resolved for classification and reported in the header — a symlink to a 4 GB file previews the target under the target’s budget, and the header says where it points. A broken symlink is a Gone-adjacent state with the dangling target named, not a silent empty pane. A symlink loop is bounded by Vfs::canonicalize, which already exists for the per-folder preference key.

The renderers

The providers, one at a time

F-31 Markdown — TextView

gpui-component’s TextView parses Markdown into a document tree and renders headings, lists, tables as real tables, block quotes, task lists, links, inline code and fenced code blocks — the fences highlighted through the same LanguageRegistry the code provider uses, so a Rust block in a README and a .rs file get identical colours for free.

Rust library decision: reuse markdown-rs (crate markdown, locked at 1.0.0), which the pinned component already calls through markdown::to_mdast in text/format/markdown.rs. It supplies parsing; TextView supplies native GPUI layout. An HTML-producing crate alone does not supply a native renderer. Keep CommonMark plus GFM tables, task lists and strikethrough; executable MDX, raw HTML rendering, math and diagram execution are out of scope.

  • Own persistent state. Hold one TextViewState per active document and update it outside Render. Background parsing does not prove virtualised layout: benchmark nested lists, wide tables, many fences and long paragraphs before accepting the rendered mode.
  • Resolve resources structurally. Inspect parsed image nodes, including reference images and HTML image syntax; never use regex rewriting. Raw HTML and MDX constructs remain inert source text. Default all images to alt text until a renderer hook can inject only validated, predecoded bitmaps. The pinned URI-based image helper is not such a hook; a small reviewed component extension is a prerequisite for local images. Do not rewrite to file://.
  • Document-scoped images. Permit only relative local paths beneath the canonical document directory. Reject absolute paths, URI schemes, UNC paths, traversal, and symlink/junction escapes. Open and verify the resolved file identity before reading, then apply the same byte, pixel and memory limits as F-33. Deny resources from remote mounts by default. At most 16 images, 8 MiB encoded and 32 MiB decoded in aggregate per document; placeholders retain alt text.
  • Link policy. Same-document anchors scroll within the document. Relative file links navigate only on a click through the browser’s normal navigation and dirty-buffer guard. External https, http and mailto links require an explicit click with destination confirmation; reject all other schemes. Never auto-open a link or execute a Markdown task checkbox.
  • Graceful fallback. Offer Rendered / Source without changing the file. If layout exceeds its gate or syntax is unsupported, show bounded read-only source with a reason. Start with 256 KiB rendered Markdown, 4,000 blocks and nesting depth 32; exceeding structural limits falls back to source. Parsing deadlines are cooperative unless isolated in a process.

Alternatives: pulldown-cmark is the fallback if measured parser performance or event-level resource control requires an adapter. Do not add a second parser by default or round-trip source through HTML. markdown-rs already provides an AST suitable for structural policy; integration and layout limits still need proof.

F-32 Code — read-only Editor

EditorState::new(window, cx).language(name).line_number(false).soft_wrap(false), rendered through Editor::new(&state).readonly(true). Its element lays out only the visible line range, so a 20,000-line file costs the same per frame as a 20-line one.

The pane owns one Entity<EditorState> and calls set_value plus set_highlighter when the selection changes, for the same reason as Markdown. Scroll position resets; the language changes with the file; the renderer is shared with F-36, which additionally requires lossless encoding metadata, a complete buffer, save capability and navigation guards.

Line numbers default off — the reference screenshot has none and a preview is for reading, not for citing — and are a persisted toggle in the overflow menu. Soft wrap defaults off for code and on for plain text and logs, which is the split that matches how people actually read those two things.

F-33 Images — our decode, GPUI’s draw

gpui::img() already handles AVIF, JPEG, PNG, GIF, WebP, TIFF, TGA, DDS, BMP, ICO, HDR, EXR, the PNM family, QOI and SVG, with animated GIF and animated WebP decoded to frame sequences. The formats are not the problem. The path is: GPUI’s loader does a blocking whole-file read and a full-resolution decode, which is right for a bundled 24 px icon and catastrophic for a photographer’s directory.

So ferret-preview::image owns the pipeline and GPUI only draws the result:

  1. Probe the header for dimensions without decoding. Past IMAGE_SOURCE_PIXEL_CAP the answer is TooLarge and no allocation happens at all.
  2. Read under the kind’s byte budget, decode off-thread with the decoder’s own allocation limits set.
  3. Downscale to the pane’s long edge at the window’s scale factor, capped at 4096 px, with a triangle filter — a low-cost baseline to compare visually against Lanczos; triangle filtering is bilinear, not a distinct quality class.
  4. Convert to BGRA and hand ferret-ui a Bitmap, which becomes one RenderImage.

Animation. Animated GIF and WebP are decoded to frames and played only in the docked pane and the F-75 overlay, never in icon-view thumbnails — a directory of forty animated GIFs must not become forty running animations. A frame count past ANIMATION_FRAME_CAP falls back to the first frame with a footer note.

SVG. Rasterise off-thread into a bounded bitmap. First verify the pinned SVG renderer can disable external images, fonts and filesystem/network resolution; otherwise show source. Cap source bytes, node count, nesting, filter intermediates and output pixels: viewBox dimensions alone do not bound complexity. Debounce resizing and reuse the last bitmap while a replacement is prepared.

HEIC and RAW. The image crate decodes neither, and they are two of the most common things in a real Pictures folder. Both use PV-D07’s best-effort OS thumbnail path. Codec and handler availability varies; absent support shows metadata and Open externally.

Thumbnails. Icon view asks ferret-preview::thumbs, which is a disk cache under the user’s cache directory keyed by a hash of canonical path, mtime, size and target pixel size. Size in the key is the part that is easy to omit and matters: a file edited without its mtime changing is rare, but a file replaced with one of a different length is not. Entries are 128 px WebP, evicted by age past THUMB_CACHE_AGE and by total bytes past THUMB_CACHE_BYTES, oldest first. Generation is bounded to visible tiles plus a small lookahead, on ferret_vfs::pool, never on a fourth thread pool.

F-35 CSV and TSV — table

Delimiter sniffed from the first 64 KiB by scoring comma, tab, semicolon and pipe on consistency of field count across the first 20 complete logical records parsed with quote handling — the frequency-only heuristic gets European semicolon-delimited exports wrong often enough to matter. Header detection: the first row is a header if every one of its fields is non-numeric and at least one subsequent row has a numeric field in the same column.

Parsed with the csv crate, because RFC 4180 quoting — embedded delimiters, embedded newlines, doubled quotes — is precisely the kind of thing that looks like twenty lines of hand-rolled code and is wrong on real data. The initial implementation parses a bounded 2 MiB prefix into at most 2,000 records, 128 columns and 32 MiB of cell data, with a 64 KiB per-field limit. Render with the virtualised table; a 500 MB file opens as an explicitly labelled sample. Scrolling never silently reads the rest. True incremental loading requires a future cancellable streaming/range VFS contract.

Column sorting is offered only within what has been loaded, and says so, rather than pretending to sort a file it has not read. Header inference is a reversible toggle; use Column 1…N when uncertain. Ragged records get a marker; unrecoverable syntax shows a byte/record location and a source fallback. An incomplete final record at the byte cap is omitted with an explicit truncation note — a preview that hides the broken row is worse than useless for the person trying to find it.

F-30 Plain text, logs, and the binary floor

Text with no language resolves to the Plain language and renders in the same editor with soft wrap on. Line endings are detected and reported in the header (LF / CRLF / mixed) because that is load-bearing information the moment F-36 is involved. A UTF-16 or UTF-8 BOM is decoded and noted. Invalid sequences may render as U+FFFD only in an explicitly labelled lossy read-only view; unknown invalid text defaults to hex.

Binary is the floor and is a real view, not an apology: 16 bytes per row, offset gutter, hex, printable ASCII column, for the first HEX_BUDGET bytes. It is what makes “what actually is this file” answerable without leaving the app.

F-75 Space-to-preview

The same Preview value rendered into a full-window overlay mounted on Root’s dialog layer. Deliberately not deferring to macOS Quick Look’s own panel: sharing the provider means the two surfaces cannot disagree, and the overlay works identically on Windows where there is no Quick Look panel to defer to. The OS thumbnail service is still used underneath for types we cannot render — it is a data source, not a UI.

Because the value is already computed for the docked pane, Space on an already-previewed selection opens instantly with no read at all. When the pane is closed, the overlay runs the same pipeline on demand.

The cost, stated plainly

Cold-build and stripped-binary deltas are unmeasured; record both for the locked grammar set on macOS and Windows before release. So the extended set sits behind a default-on languages-extended feature forwarded from the binary crate to ferret-ui: on for anyone who builds normally, and --no-default-features away for someone iterating on the file pane who does not care about Gleam. The built-in 35 are never optional — a code preview with no colour is a broken feature, not a fast build.

Q-01, answered

PDF, and everything else the OS already knows

Q-01 is resolved in favour of reliable PDF coverage: official builds bundle Pdfium and use pdfium-render to render bounded page bitmaps in a helper process. This accepts packaging cost to meet the product requirement. Native thumbnails remain a fast path and extend coverage to other document types; they cannot replace a guaranteed PDF backend.

PDF acceptance contract

Render page one automatically, show “Page 1 of N”, and provide Previous / Next plus a page-number field, fit-to-width and zoom. Keep only the current page and at most one neighbour within the shared bitmap budget. Parse and render off-process; cancel stale requests and terminate a timed-out helper. Never execute PDF JavaScript, launch actions, attachments or embedded media. Encrypted PDFs show a Protected state and Open externally in v1; corrupt or over-budget files have explicit failure states.

PDFs require random access and can place their index at the end. Load complete bytes only for files within PDF_BUDGET (64 MiB local, 16 MiB remote), not a truncated head; larger files show TooLarge. Supply bounded bytes to the helper rather than an unrestricted path. A five-second render deadline and 256 MiB helper memory ceiling are initial targets to verify on both platforms. Start by testing page rendering on clean installations with no PDF thumbnail handler.

Contract

Performance contract

Phase 3’s acceptance in docs/plan.html is “arrow-keying down a directory of mixed file types renders each preview without a dropped frame”. That sentence is the whole contract, and it is satisfied by four rules.

  1. Debounce, then one generation. A selection change bumps preview_generation and schedules work at PREVIEW_DEBOUNCE (80 ms). Continuous key-repeat produces one settled request. Drop cancels interest, not an already-running blocking syscall or decoder. Keep one active preview job and one replaceable pending request, check cancellation between stages, and reject stale generations on arrival. Clear the old body immediately so new metadata never labels old content. Closing the pane cancels interest; the overlay may retain it. Watcher updates invalidate clean previews; dirty buffers enter Conflict.
  2. Nothing O(the file) on the main thread. Reading, sniffing, decoding, downscaling and CSV parsing all run on ferret_vfs::pool or through smol::unblock. Library work is included in the budget: measure state updates, parsing, highlighting and layout. Run data-parallel work only inside ferret_vfs::pool; do not create implicit Rayon pools. File I/O may use the existing blocking executor. Long-line files get a 16 KiB displayed-line cap or source fallback before layout.
  3. The render path reads, and only reads. Render for the preview pane matches on a Preview and builds elements. It does not clone the text, re-derive a language, re-scan for line endings or rebuild a bitmap. just budget is the mechanical check, and the preview pane joins the allocation-budget test with its own case: arrow through ten files of ten kinds and assert the per-frame allocation count is flat.
  4. Budgets are hard, and stated. Every read is capped; every cap has a footer line when it bites. Rust reads and decodes are bounded; native providers have the explicitly documented exception above. A 128 MiB aggregate working-memory target includes input, decoder scratch, RGBA/BGRA copies and retained frames; a separate 64 MiB resident bitmap budget includes GPU uploads. Reserve before starting a job, fall back on refusal, and measure process/GPU peaks because decoder limits alone do not enforce this accounting.

Measure release builds with machine, OS, refresh rate, fixture size and cold/warm cache recorded. Report p50/p95 over 30 settled selections and compare 60 Hz frame times against the same navigation with preview disabled. Initial gate: p95 frame ≤ 16.7 ms and no preview-attributable stall over 33 ms. At 120 Hz also report missed 8.3 ms intervals. Selection-to-content includes the 80 ms debounce: target ≤ 150 ms p95 for small text/Markdown and ≤ 500 ms for ordinary images/PDF page one. A cache hit should appear on the next frame. CPU-only xtask measurements cannot certify GPUI frame, layout or GPU upload performance.

Safety

Safety and privacy

A preview pane renders files the user did not write, did not choose and may have just downloaded. That is a different threat model from an editor opening a project, and three things follow from it.

  • No document-initiated network (PV-D10). The single most likely quiet failure in this whole feature is a Markdown file with ![](https://tracker.example/pixel.png) silently confirming to a third party that this machine opened this file. GPUI will happily fetch it. All raw resource URLs are blocked; the resolver alone supplies bounded bitmaps. Verify with a request-counting local HTTP server and assert zero requests, including HTML, reference images and SVG resources.
  • No path escapes. A rewritten relative image URL is normalised and rejected if it leaves the document’s directory. ![](../../../.ssh/id_rsa) renders as alt text. Canonical containment and opened-file identity are required as well as lexical normalisation; test symlinks, Windows junctions, UNC/device paths and encoded traversal.
  • Every decoder gets limits. Decompression bombs are the standard attack on exactly this surface — a 40 KB PNG that decodes to 60 GB. The pixel cap is checked from the header before allocation, and the decoder’s own Limits are set as the backstop for formats where the header lies.
  • The OS renders out-of-process where it can. Quick Look generation runs outside our address space, so a malformed PDF crashes Apple’s helper and returns an error, not a crash. Windows native failures must be contained in the supervised helper; Rust panic handling and a thread timeout do not catch access violations or stop a hung COM call.
  • Nothing the preview reads is ever written back. Except through F-36, which is explicit, confirmed and atomic.
Mounts

Remote mounts

Phase 8 compatibility, not an existing implementation: the current VFS exposes backend-wide capabilities() and bounded-buffer read. A future mount router must supply per-path capabilities and explicit freshness. No Router, capabilities_for or invalidate API exists today; these names below describe required semantics, not methods ready to call.

  • Budgets scale down. REMOTE_BUDGET_SCALE is ¼. A 2 MiB text budget over a 200 ms-RTT link is several seconds of waiting for something the user was arrow-keying past; 512 KiB is a preview.
  • The loading state is not optional. Locally the 120 ms threshold means the skeleton rarely appears. Remotely it always will, and it says “Reading over the connection” rather than showing a generic spinner, because the user needs to know which kind of slow this is.
  • Ask capabilities_for(path), never capabilities(). The Edit button’s existence is a property of the backend the file is on. A read-only mount shows no Edit button rather than an Edit button that fails on save.
  • There is no watcher. Do not assume a remote watcher or cache lifetime. Manual refresh must request fresh metadata and bytes from the future backend, bypassing cached metadata. Its invalidation API is deferred with the mount implementation.
  • The OS thumbnail path is local-only. Quick Look and the shell take a filesystem path. A remote PDF downloads completely only within its reduced budget and uses Pdfium, or shows metadata and Open with…, which for a mount means downloading it deliberately. It does not silently pull 40 MB over SSH because someone moved the selection.
F-36

Edit mode

The smallest feature in this plan with the largest downside. R-06 names data loss as the worst thing this product can do, and in-place save is the one place the preview pane can do it.

Proposed local save surface. The trait has read but no write, so this and FileIdentity are proposed new types/API, subject to the conflict contract below:

/// Replace a file's contents, atomically.
///
/// Writes a temporary file in the *same directory* — a different filesystem
/// makes the final step a copy, which is exactly what atomicity rules out —
/// flushes it, then renames over the target. A reader either sees the old
/// bytes or the new ones, never a truncated file, and a crash mid-write
/// leaves the original intact.
///
/// `expect` is the identity the caller last saw. A mismatch is refused
/// rather than resolved: the file changed under the editor, and only the
/// person looking at both versions can say what should win.
async fn write_atomic(
    &self,
    path: &VfsPath,
    contents: &[u8],
    expect: FileIdentity,
) -> Result<FileIdentity>;

Around that:

  • Preserved on save: the file's existing line endings (a CRLF file stays CRLF even though the editor works in LF), the presence or absence of a trailing newline, the BOM if there was one, and Unix permission bits. Ownership where the platform allows it.
  • Refused: binary files; files that were truncated by the budget, because saving a truncated buffer would destroy the tail; and any file whose mtime or size changed since load.
  • Confirmed: navigating away with unsaved changes. The selection change is blocked, not queued — a preview that silently discards an edit because the user pressed ↓ is the data-loss failure in miniature.
  • Windows: implement replacement with verified ReplaceFileW semantics, including ACLs, sharing violations and open handles. Never delete the destination first. On Unix, sync the temporary file and parent directory where supported. Atomic visibility and crash durability are distinct; report durability failures without blindly retrying a replacement that may have committed.
  • Remote: SFTP has no atomic replace primitive that is universally available. editing stays disabled unless the backend explicitly advertises atomic replacement with the required conflict checks. A generic writable or rename capability is insufficient; there is no delete-then-rename fallback.

Conflict and fidelity contract. Snapshot original bytes plus file identity (mount, resolved path, file ID where available, size, high-resolution mtime and content hash). Revalidate immediately before replacement; same-size/same-mtime edits still conflict. Ordinary filesystem replacement is not compare-and-swap against arbitrary external writers: there remains a check-to-replace race. Preserve a recoverable pre-save copy and expose conflicts honestly; do not promise strict concurrency safety. Route the user mutation through ferret-ops under D-09, with storage mechanics in ferret-vfs. A successful save returns the new identity; ambiguous completion triggers a read-back rather than automatic retry.

V1 editing is limited to complete, losslessly decoded UTF-8/UTF-16 text with uniform LF or CRLF. Preserve encoding, BOM and final-newline state from the original buffer; unmodified Save is a no-op. Mixed endings, invalid encoding, UTF-32, symlinks/reparse points and multiply linked files remain read-only until their fidelity semantics are explicitly implemented. Verify Unix mode and relevant macOS extended metadata, Windows ACLs/attributes and replacement behavior; fail before changing content if required metadata cannot be preserved. Saving and Conflict are explicit UI states. No autosave.

Tests for this are the highest-value tests in the feature, against temp directories: CRLF round-trip, no-trailing-newline round-trip, BOM round-trip, permission preservation, concurrent-modification refusal, and a byte-identical round-trip of a file that was opened and saved without being edited.

Done when a 400-page PDF scrolls with constant resident-page limits; rapid jumps cancel stale renders and repeated zoom does not grow memory.

Questions this plan closes

Q-01

Decided. Bundle Pdfium in official builds on both platforms; page one and page navigation are required, independent of installed native handlers. Accept packaging and isolation work to meet the requested PDF experience. Continuous scrolling is a follow-up.

Q-02

Closed. The built-in 35 always; ~30 more registered through the public registry behind a default-on feature; ~150 further extensions identified but not highlighted. Runtime-loadable grammars are not worth the complexity — the registry already makes compile-time registration a one-line addition per language.

Preview questions resolved

PV-Q01

Selection, consistently. Exactly one selected item previews; two or more show an aggregate summary in both pane and overlay. Cursor movement inside a multi-selection never secretly picks a file. Use cached selection aggregates; mark unknown sizes as unknown and never scan the directory during Render or marquee movement.

PV-Q02

One pinned edit buffer, no per-tab unsaved workspace. Guard selection, navigation, tab switch/close, pane collapse, overlay dismissal and app quit with Save / Discard / Cancel on both platforms. Save failure keeps the buffer and focus intact. Cancel restores the original selection; only the explicitly requested transition resumes after Save or Discard. A resize may hide the pane but must not discard its buffer.

PV-Q03

No libheif in this phase. Use best-effort native thumbnails for HEIC/RAW, with metadata fallback when codecs are absent. Linux remains deferred under D-19; revisit only against demonstrated coverage requirements and measured packaging cost.

These are planning decisions, not completed implementation. Remaining evidence gates are the Markdown resource hook and layout, grammar ABI/query compatibility, native coverage and process isolation, and save fidelity on each filesystem. A failed gate selects the documented fallback; it does not silently weaken the contract.
