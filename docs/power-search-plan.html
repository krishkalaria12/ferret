Detailed implementation plan · F-40–F-43 · 30 Aug 2026

Power Search, at filesystem speed.

A streaming, cancellable filename and content search for Ferret. It opens from a right-side top-bar toggle, preserves every control visible in the supplied reference, and adds the smallest set of high-value capabilities that do not compromise latency.

Owner
ferret-search + ferret-ui
Mode
Index-free, in-process
Targets
macOS · Windows
Primary gate
<100 ms first local result
Decision summary

Executive verdict

Build the existing Phase 4 commitment as one modal Power Search surface, but keep the engine independent of GPUI. One filesystem walk feeds filename matches and content workers concurrently; bounded channels stream batches into a virtualized result table; generation IDs and cancel-by-drop prevent stale work from reaching the UI.

Recommended baselineignore for traversal and ignore rules; grep-searcher + grep-regex for content; existing async-channel/smol for bounded delivery and tasks; no persistent index, no subprocess, no new async runtime.
PS-D01

Search live disk, not an index. This preserves F-40, starts with zero warm-up, returns current truth, avoids a privacy-sensitive database of paths/content, and works for removable roots. Reconsider only after measured user traces show repeated whole-home scans are the bottleneck.

PS-D02

Literal by default; regex is explicit. Literal search enables the fastest prefilters. Regex compilation happens once per query with conservative pattern/compiled-size limits and inline errors.

PS-D03

Stream discovery order; rank only a bounded window. Global sorting delays the first result and disables traversal parallelism. The UI may rank the currently retained filename batch, but never wait for the walk to finish.

PS-D04

One query generation owns all work. Changing query, filters, or scope drops the old receiver and sets a shared cancellation flag. Every batch carries its generation; stale batches are ignored defensively.

Included additions

  • Smart-case as the default, plus explicit case-sensitive mode; fixed-string/regex toggle; whole-word toggle for content.
  • Include hidden, respect ignore files, follow symlinks, and same-filesystem toggles under an expandable Options row.
  • Date and size ranges from F-42; exclusion globs; maximum depth; custom scope; recent searches stored as query settings only—never results or file content.
  • Content result context, highlighted match, file/line/column, copy path, reveal, open, Space preview, and keyboard navigation.
  • Clear disclosure when results are capped, files are skipped, access is denied, a remote backend is filename-only, or the query is still running.

Non-goals for first delivery

  • No persistent content index, background daemon, OCR, semantic/vector search, archive decompression, PCRE2, or searching inside proprietary document formats.
  • No attempt to provide regex backreferences/look-around; the Rust regex syntax is fast and bounded precisely because those are excluded.
  • No global result sort that waits for completion. No unlimited result retention. No UI-thread filesystem access.

Ownership and data flow

Architecture

01 · ferret-uiQuery snapshot

Inputs, scope, generation, filters. GPUI owns display state only.

02 · ferret-searchPlanner + walker

Compile matchers once. Traverse in parallel. Apply cheap metadata gates first.

03 · worker poolContent scan

Bounded work queue, per-worker searcher, cancellation checks between files and matches.

04 · bounded streamBatched results

Generation-tagged batches, progress deltas, warnings, terminal outcome.

New crate: ferret-search

This is the point at which a second service needs VfsPath/EntryKind. Prefer moving only truly shared domain types to ferret-core if necessary; do not make ferret-search depend on ferret-ui or gpui-component. The first implementation may accept local PathBuf roots and a capability-aware remote adapter later, but the public request/result types must not assume slash paths.

SearchService::start(SearchRequest) -> SearchSession
SearchSession { events: Receiver<SearchEvent>, cancel-on-drop }
SearchEvent = Batch { generation, results } | Progress(...) | Warning(...) | Finished(...)
SearchResult = File { path, metadata } | Content { path, line, column, ranges, preview }

Backpressure and scheduling

  • Use a bounded file-work queue and bounded UI-event channel. A slow frame must park search producers instead of materializing the tree.
  • Batch by count or a short deadline (for example 64 rows or 8 ms), whichever comes first. Notify GPUI once per batch, not once per match.
  • Reserve one CPU for the UI on machines with more than two logical cores; make thread count configurable and benchmark the heuristic.
  • Check cancellation before metadata work, before opening a file, after each file, and from the match sink. Dropping a session must stop observable output immediately.
  • Keep result data compact: shared root + relative paths where practical; bounded preview bytes; no entire file bodies; never load all results merely to sort.

UI integration points

  • Add TogglePowerSearch in ferret-ui/src/actions.rs; bind both platform shortcuts in the binary; add a bundled search icon.
  • Add the toolbar button in browser/title_bar.rs right action group. Mount a gpui-component dialog under the existing Root.
  • Keep the long-lived modal state in a focused search/ UI module, not in the already-busy browser render file. Results use Table/virtual_list.
  • Opening a result navigates the active tab by default. Modifier behavior opens a new tab. Content results carry a future preview/editor location without coupling the engine to preview UI.

Benchmark matrix

  • Flat 200,000-entry fixture; deep tree; many tiny files; few multi-GB files; binary-heavy tree; generated minified lines; inaccessible directories; symlink cycle; Unicode names; cold and warm filesystem cache.
  • Literal rare/common, regex anchored/unanchored, Unicode classes, case-insensitive, filename-only, content-only, combined filters, cap-hit, cancel after 1/10/100 ms.
  • macOS APFS (case-sensitive and insensitive if available), Windows NTFS, removable/network volume. Report CPU count, storage, cache state, files/bytes scanned, ignored/skipped counts.

Important implementation corrections to the older product plan

  • Do not force mmap for “large files.” Ripgrep’s own documentation notes buffered reads usually win for directory searches; let the searcher choose and benchmark any threshold.
  • Do not make “sort results” the default. Ripgrep documents path sorting as disabling parallelism. Stream discovery order and offer post-completion sorting only when the retained set is bounded.
  • Do not send every hit to GPUI. Batch results and coalesce progress. The table must be virtualized from its first rendered row, satisfying the same gate as the base file pane.

Gated build order

Delivery sequence

Each stage leaves the workspace runnable. Do not advance when its gate fails.

PS-0

Lock semantics and fixtures

Write request/result/error types, query truth table, platform matrix, benchmark fixtures, and budgets before choosing UI details. Gate: tests cover smart case, globs, paths, cap, cancellation, and partial errors.

PS-1

Create the service skeleton

Add ferret-search, crate error/config modules, streaming session, cancel-by-drop, bounded channels, and fake engine tests. Gate: drop prevents every later generation event.

PS-2

Filename walk (F-40)

Integrate ignore; kinds, hidden/ignore/symlink policy, scope, extension/date/size/depth filters; streaming progress. Gate: 200k fixture meets first-result, memory, cancellation budgets.

PS-3

Modal shell and toolbar toggle

Add actions, icon, platform keybindings, Root-hosted dialog, focus trap/restore, fields, scope tabs, and virtual results. Gate: launch app; inspect both themes and minimum/default sizes; arrows follow focus; table stays smooth under peak stream.

PS-4

Content scan (F-41)

Add per-worker grep-searcher/grep-regex, literal/regex/word/case modes, binary and encoding policy, context preview, match locations. Gate: first-match and instant-cancel budgets across corpus matrix.

PS-5

Complete filters and scopes (F-42/F-43)

Add range controls, exclusions, custom folder, volume roots, remembered non-sensitive preferences, capability-aware remote surface. Gate: no local-path assumptions leak into public result identity.

PS-6

Actions, accessibility, resilience

Open/reveal/copy/preview hooks, result caps, partial warnings, screen-reader names, keyboard parity, IME-safe debouncing, stale-path behavior. Gate: complete interaction/state checklist on both platforms.

PS-7

Profile and harden

Flamegraphs/allocations, cold-cache runs, long soak/cancellation storms, corrupted/unreadable files, regex limits, dependency/license audit. Gate: just lint, just test, search benchmarks, just build, and manual just dev verification all pass.

Acceptance

Verification checklist

Automated

  • Unit tests: parser/builders, case rules, extension/glob normalization, metadata predicates, result IDs, truncation, error conversion, counters.
  • Filesystem integration: temp trees, nested ignore precedence, hidden files, Unicode/non-UTF paths where supported, binary/BOM/UTF-16, huge line, permission denial, changing/deleted files, symlink cycles.
  • Concurrency: bounded queues, cancel races, rapid generation churn, receiver drop, cap reached, worker panic/error containment, no events after Finished.
  • UI tests where GPUI support permits: open/close, focus restore, stale generation rejection, stable selection as batches arrive, empty/error/cap states.
  • Benchmarks checked into xtask or the search crate with machine-readable output and regression thresholds.

Manual on both targets

  • Open by button and shortcut; close by toggle, Done, Esc; focus returns to the top-bar control or prior pane.
  • Light/dark, 1180×760 and 760×480; 100%, 150%, 200% scaling; keyboard-only and screen-reader labels.
  • Rapid typing never flashes stale results. Selection does not jump when rows append. Cancel leaves no sustained CPU/disk use.
  • Search Home/Computer, removable volume, denied tree, very large tree, and a path removed while selected.
Feature-level done conditionA regex content search over a large tree begins producing useful rows in well under one second, filename search typically feels immediate, a changed query cancels old work before it can repaint, the results table stays at full frame rate, and memory remains bounded even when every line matches.
Honest uncertainty

Risks and open decisions

PS-Q01 · Should filename search offer fuzzy mode at launch?

Recommendation: no for the first vertical slice; add a visible optional mode only if a Nucleo prototype meets streamed-order and selection-stability requirements. Substring semantics match the reference and are easier to explain.

PS-Q02 · What exactly is “Root” on Windows?

Recommendation: label it “Computer” and search selected mounted volumes, with all fixed local volumes as an explicit option. Avoid automatically scanning network/removable volumes.

PS-Q03 · How much context should content results retain?

Recommendation: one bounded display line plus match ranges and line/column. Read neighboring context lazily for preview; never retain whole file bodies.

PS-Q04 · When should indexing be reconsidered?

Only after telemetry-free local benchmarks or user-provided traces show repeated Home/Computer searches cannot meet the experience target. Any experiment must be opt-in, path-only first, encrypted-by-OS-at-rest, size-capped, rebuildable, watcher-plus-reconciliation based, and must preserve live verification before opening a result.

PS-Q05 · Remote content search contract

F-43 leaves this genuinely backend-specific. Prefer a capability enum and explicit UI. An SSH backend may run remote rg/grep when available; S3/WebDAV are filename/metadata-only until a server-side search API exists. Never download an entire remote tree implicitly.

Primary risks

  • I/O saturation: unbounded parallel reads can make the whole machine feel slow. Bound content workers separately from traversal and preserve one CPU for UI.
  • Stale paths: the filesystem changes mid-query. Treat results as observations; re-stat on action and explain if the item moved or vanished.
  • Regex/resource abuse: linear matching is not free. Cap pattern length, compiled program size, file size, context, matches per file, total rows, and retained bytes.
  • Permission noise: whole-machine search can generate thousands of denials. Aggregate by category/root, keep useful results visible, and expose details on demand.
  • Scope creep: fuzzy ranking, archives, indexing, OCR, semantic search, and remote execution are separate capabilities. Do not block the fast local core on them.
